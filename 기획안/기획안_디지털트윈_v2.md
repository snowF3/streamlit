# 디지털 트윈 v2 — 개발 기획서

## 0. 배경 및 방향 전환

### 기존 기획(v1)의 문제점

기존 기획은 "합성 시민 30만명이 지도 위에서 이동하는 애니메이션"이 핵심이었으나, 다음과 같은 근본적 한계가 확인됨:

1. **생태학적 오류(Ecological Fallacy)**: 법정동 단위 집계 데이터를 개인 수준으로 역분해하면 변수 간 결합분포를 알 수 없어 허구적 개인이 생성됨
2. **OD 데이터 부재**: 각 동의 시간대별 "존재 인구"만 있고 "누가 어디서 어디로 이동했는지" 정보가 전혀 없음. 점의 이동 경로는 100% 허구
3. **Streamlit 기술 제약**: 프레임 단위 애니메이션 불가, 매 상호작용마다 전체 리렌더링, pydeck 클릭 이벤트 불안정
4. **거짓 정밀도(False Precision)**: 법정동 집계 데이터를 개별 점으로 시각화하면 "저 사람이 저 골목에 있다"고 오해 유발

### v2 방향

- **데이터에 정직한 시각화**: 법정동 단위 코로플레스/3D 맵으로 "도시가 숨 쉬는" 느낌 구현
- **MiroFish 확장성 확보**: 당장 AI 에이전트 시뮬레이션은 구현하지 않되, 나중에 연결 가능한 데이터 레이어와 인터페이스를 선제 설계
- **질문형 인터페이스**: "데이터를 보여주는" 대시보드가 아니라 "질문에 답하는" 서비스

### MiroFish란?

> https://github.com/666ghj/MiroFish

AI 에이전트 수천 개가 상호작용하며 미래를 시뮬레이션하는 예측 엔진.
- 시드 데이터(텍스트/보고서) → GraphRAG(지식그래프) 구축
- 엔티티 관계 추출 → 페르소나(에이전트) 생성
- OASIS 프레임워크 기반 병렬 시뮬레이션 + 동적 메모리(Zep Cloud)
- 시뮬레이션 결과 → 예측 보고서 자동 생성

최종 비전은 이 방식을 서울시 상권/인구 예측에 적용하는 것이며, Phase 1~2에서는 그 밑거름을 깔아둔다.

## 1. 데이터 아키텍처

### 3-Layer 구조

```
[Layer 1: Raw]          Snowflake 원본 (SPH/리치고/아정당)
       ↓
[Layer 2: Curated]      분석용 정규화 뷰 + 파생 지표
       ↓
[Layer 3: Semantic]     MiroFish용 프로파일 텍스트 + 페르소나 JSON
```

- Layer 2만 잘 만들면 MiroFish 전환 비용은 "Jinja 템플릿 작성" 수준으로 줄어듦
- Streamlit은 Layer 2를 직접 시각화, Layer 3은 향후 MiroFish/외부 서비스용

### Layer 2 — Snowflake 뷰 설계

#### V_DIM_DONG_PROFILE (동네 요약 프로파일)

핵심 파생 지표 포함:

```sql
CREATE OR REPLACE VIEW SPH_CURATED.V_DIM_DONG_PROFILE AS
WITH pop AS (
  SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH,
    SUM(RESIDENTIAL_POPULATION) AS res_pop,
    SUM(WORKING_POPULATION) AS work_pop,
    SUM(VISITING_POPULATION) AS visit_pop
  FROM FLOATING_POPULATION_INFO
  GROUP BY 1, 2
),
pop_time AS (
  SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH,
    SUM(CASE WHEN TIME_SLOT IN ('T06','T09','T12')
      THEN RESIDENTIAL_POPULATION+WORKING_POPULATION+VISITING_POPULATION END) AS day_pop,
    SUM(CASE WHEN TIME_SLOT IN ('T18','T21','T24')
      THEN RESIDENTIAL_POPULATION+WORKING_POPULATION+VISITING_POPULATION END) AS night_pop
  FROM FLOATING_POPULATION_INFO GROUP BY 1, 2
),
sales AS (
  SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH,
    SUM(TOTAL_SALES) AS total_sales,
    SUM(TOTAL_COUNT) AS total_count,
    SUM(COFFEE_SALES) AS coffee_sales,
    SUM(FOOD_SALES) AS food_sales
  FROM CARD_SALES_INFO WHERE CARD_TYPE='1' GROUP BY 1, 2
),
income AS (
  SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH,
    SUM(CUSTOMER_COUNT) AS customers,
    SUM(CUSTOMER_COUNT*AVERAGE_INCOME)/NULLIF(SUM(CUSTOMER_COUNT),0) AS avg_income,
    SUM(CUSTOMER_COUNT*AVERAGE_ASSET_AMOUNT)/NULLIF(SUM(CUSTOMER_COUNT),0) AS avg_asset
  FROM ASSET_INCOME_INFO WHERE INCOME_TYPE=1 GROUP BY 1, 2
)
SELECT
  m.DISTRICT_CODE, m.CITY_KOR_NAME, m.DISTRICT_KOR_NAME,
  p.STANDARD_YEAR_MONTH,
  p.res_pop, p.work_pop, p.visit_pop,
  p.res_pop + p.work_pop + p.visit_pop AS total_pop,
  pt.day_pop, pt.night_pop,
  -- 파생 지표
  ROUND(pt.day_pop / NULLIF(pt.night_pop, 0), 2) AS day_night_ratio,
  p.visit_pop / NULLIF(p.res_pop + p.work_pop + p.visit_pop, 0) AS visit_ratio,
  s.total_sales, s.total_count,
  ROUND(s.total_sales / NULLIF(p.res_pop + p.work_pop + p.visit_pop, 0), 0) AS sales_per_capita,
  i.avg_income, i.avg_asset, i.customers
FROM M_SCCO_MST m
LEFT JOIN pop p ON m.DISTRICT_CODE = p.DISTRICT_CODE
LEFT JOIN pop_time pt ON m.DISTRICT_CODE = pt.DISTRICT_CODE
  AND p.STANDARD_YEAR_MONTH = pt.STANDARD_YEAR_MONTH
LEFT JOIN sales s ON m.DISTRICT_CODE = s.DISTRICT_CODE
  AND p.STANDARD_YEAR_MONTH = s.STANDARD_YEAR_MONTH
LEFT JOIN income i ON m.DISTRICT_CODE = i.DISTRICT_CODE
  AND p.STANDARD_YEAR_MONTH = i.STANDARD_YEAR_MONTH;
```

#### V_FACT_HOURLY_FLOW (시간대별 흐름)

```sql
CREATE OR REPLACE VIEW SPH_CURATED.V_FACT_HOURLY_FLOW AS
SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH, WEEKDAY_WEEKEND, TIME_SLOT,
  SUM(RESIDENTIAL_POPULATION) AS res_pop,
  SUM(WORKING_POPULATION) AS work_pop,
  SUM(VISITING_POPULATION) AS visit_pop,
  SUM(RESIDENTIAL_POPULATION+WORKING_POPULATION+VISITING_POPULATION) AS total_pop
FROM FLOATING_POPULATION_INFO
GROUP BY 1, 2, 3, 4;
```

#### V_FACT_CONSUMPTION_MATRIX (소비 DNA + HHI)

```sql
CREATE OR REPLACE VIEW SPH_CURATED.V_FACT_CONSUMPTION_MATRIX AS
SELECT DISTRICT_CODE, STANDARD_YEAR_MONTH,
  SUM(TOTAL_SALES) AS TOTAL_SALES,
  SUM(FOOD_SALES) AS FOOD_SALES,
  SUM(COFFEE_SALES) AS COFFEE_SALES,
  -- ... (19개 업종 생략)
  -- HHI (소비 집중도): 각 업종 비율^2의 합
  POWER(SUM(FOOD_SALES)/NULLIF(SUM(TOTAL_SALES),0), 2)
    + POWER(SUM(COFFEE_SALES)/NULLIF(SUM(TOTAL_SALES),0), 2)
    + ... AS consumption_hhi
FROM CARD_SALES_INFO
WHERE CARD_TYPE='1'
GROUP BY 1, 2;
```

### 파생 지표 정의

| 지표 | 정의 | 해석 |
|------|------|------|
| **낮밤 인구비** (day_night_ratio) | 주간(T06~T12) 총인구 / 야간(T18~T24) 총인구 | >1 오피스가, <1 베드타운 |
| **방문 비중** (visit_ratio) | 방문인구 / 총유동인구 | 높으면 상업/관광, 낮으면 주거/직장 |
| **1인당 매출** (sales_per_capita) | 총카드매출 / 총유동인구 | 소비 활성도 |
| **소비 집중도** (consumption_hhi) | 19개 업종 비율 제곱합 (HHI) | <0.05 다양, >0.2 특정업종 편중 |
| **소득-소비 갭** | 소득 백분위 - 소비 백분위 | 양수면 소비유출(잠자리 동네), 음수면 소비유입 |
| **주말 반전 지수** | 주말 방문인구 / 주중 방문인구 | >1 여가/관광형, <1 비즈니스형 |

#### `app/utils/simulation.py` — 시뮬레이션 엔진

```python
from dataclasses import dataclass
from abc import ABC, abstractmethod

INDUSTRY_PARAMS = {
    "카페":    {"capture_rate": 0.015, "avg_ticket": 5500,  "visit_freq": 2.5},
    "음식점":  {"capture_rate": 0.012, "avg_ticket": 12000, "visit_freq": 1.8},
    "미용실":  {"capture_rate": 0.005, "avg_ticket": 25000, "visit_freq": 0.8},
    "소매점":  {"capture_rate": 0.02,  "avg_ticket": 8000,  "visit_freq": 3.0},
}

@dataclass
class SimulationResult:
    monthly_revenue_low: float    # 하한 (만원)
    monthly_revenue_mid: float    # 중간
    monthly_revenue_high: float   # 상한
    peak_hours: list[str]         # 피크 시간대 top 3
    main_customer: str            # 주 고객층
    competition_index: float      # 경쟁 강도 (HHI 기반)
    risk_factors: list[str]


class SimulationEngine(ABC):
    """추상 시뮬레이션 인터페이스 — MiroFish 교체 대비"""
    @abstractmethod
    def simulate(self, district_code: str, industry: str, params: dict) -> SimulationResult:
        ...


class StatisticalEngine(SimulationEngine):
    """Phase 1: 통계 기반 (유동인구 x 전환율 x 객단가)"""

    def simulate(self, district_code, industry, params) -> SimulationResult:
        # 핵심 수식: 예상매출 = 유동인구 x capture_rate x avg_ticket x 30일
        # 소득 보정: min(해당동 avg_income / 전체평균, 1.5)
        # 리스크: day_night_ratio > 3이면 "저녁 매출 기대 낮음" 등
        ...


class MiroFishEngine(SimulationEngine):
    """Phase 2+: 에이전트 기반 시뮬레이션 (향후 구현)"""

    def simulate(self, district_code, industry, params) -> SimulationResult:
        # 페르소나 로드 → 각 페르소나의 방문 확률 x 소비액 시뮬레이션
        raise NotImplementedError("MiroFish 연동 Phase 2에서 구현")


def get_engine(engine_type: str = "statistical") -> SimulationEngine:
    engines = {"statistical": StatisticalEngine, "mirofish": MiroFishEngine}
    return engines[engine_type]()
```

이 추상화로 `chat_ui.py`의 `_simulate_business()`를 `get_engine().simulate()` 호출로 교체하면, Phase 2에서 UI 변경 없이 MiroFish 엔진으로 전환 가능.

시간대 슬라이더를 움직이면 법정동별 기둥 높이(3D) 또는 색상 농도(2D)가 변하며:
- 아침(T06): 주거지 강조
- 점심(T12): 오피스/상업지 강조
- 저녁(T18): 상업/유흥지 강조
- 심야(T21): 다시 주거지 복귀

이것이 "도시가 숨 쉬는" 디지털 트윈 효과.

### st.fragment 전략

- `@st.fragment`로 지도 렌더링 함수를 분리 → 슬라이더 변경 시 지도만 리렌더링, 하단 탭은 유지
- `st.cache_data`로 시간대별 데이터 미리 로드 → 슬라이더 변경 시 쿼리 없이 필터링만

## 6. MiroFish 연동 로드맵 (Phase 3 이후)

### 데이터 흐름

```
[현재] Snowflake Layer 2 → Streamlit 시각화

[Phase 3]
  Snowflake Layer 2
       ↓ Jinja 템플릿
  Layer 3: 프로파일 텍스트 (467개 문서)
       ↓
  MiroFish GraphRAG → 엔티티/관계 추출
       ↓
  페르소나 생성 (PERSONA_SEED 기반)
       ↓
  OASIS 병렬 시뮬레이션
       ↓
  예측 결과 → Snowflake 저장
       ↓
  Streamlit 또는 Vue.js(MiroFish 프론트)에서 시각화
```

### MiroFish Lite vs Full

| | MiroFish Lite (Phase 2) | MiroFish Full (Phase 3) |
|---|---|---|
| 에이전트 수 | 2,000~4,000 (동당 5~10) | 46,700+ (동당 100) |
| LLM | Cortex (Snowflake 내장) | Qwen-plus / Claude |
| 메모리 | Snowflake 테이블 | Zep Cloud |
| GraphRAG | 구조화 프로파일 + RAG | 풀 GraphRAG |
| 시뮬레이션 라운드 | 1~3회 | 10+ |
| 비용 | Snowflake 크레딧 | $50~500/시뮬레이션 |

### Streamlit ↔ MiroFish 연결 전략

- **공유 키**: `DISTRICT_CODE` (법정동 코드)가 양쪽의 인터페이스 계약
- **Streamlit에서 MiroFish UI 임베드**: `st.components.v1.iframe(url, height=600)` + query parameter로 법정동 코드 전달
- **외부 링크**: `st.link_button("MiroFish 상세 시뮬레이션", url)`
- **결과 공유**: MiroFish 시뮬레이션 결과를 Snowflake에 저장하면 Streamlit이 같은 테이블을 읽는 구조
